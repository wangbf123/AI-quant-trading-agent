# 研究协议与复现边界

本协议服务于日频量化因子研究。Agent 参与提出研究方向与候选，确定性计算组件负责训练、回测和评估。协议的目的在于让研究过程可复算，并减少时间泄漏、重复试验与测试集反馈带来的偏差。

## 四个时间窗口

| 窗口 | 可以做什么 | 不应做什么 |
| --- | --- | --- |
| `train` | 拟合特征处理器和模型 | 使用未来窗口拟合归一化参数 |
| `tune` | 选择模型训练参数和早停 | 与研究候选选择混为同一报告指标 |
| `research_validation` | 比较因子候选、形成经济性失败记忆、决定下一轮研究 | 把其最优表现当成最终样本外结论 |
| `sealed_holdout` | 冻结后对选定候选做一次最终评估 | 提供给提案器、作为记忆或据此在同一协议继续选因子 |

窗口必须按交易日历严格递增、不重叠。相邻窗口保留至少 **两个交易日** 的 purge gap；如果标签跨度或持有期超过两天，应增加 gap。特征滚动计算可以读取合法的过去历史，但标签、拟合和候选评估不能跨越各自允许的边界。

默认 Qlib 日频前瞻标签会读取未来价格，因此仅按特征日期切分不足以证明没有泄漏。协议需要同时记录标签表达式／跨度和被剔除的边界交易日。真实数据还需确保财报、成分股、复权与新闻在当时确实可用。

## 研究与冻结流程

协议状态按研究进度转换：

```text
draft → running → researched → frozen → finalizing → finalized
             ↘ failed / interrupted          ↘ finalization_failed
```

1. 创建协议时登记数据指纹、窗口、候选预算、成本模型及研究配置。
2. 候选在研究验证集上被评估；每次尝试均留痕，包括失败和无效候选。
3. 将相关经济性失败反馈给下一轮研究，候选评估预算按相同规则计数。
4. 完成研究后，冻结选定候选与配置摘要。冻结后的候选不能原地修改。
5. 最终评估使用原子领取，避免同时发起两个 holdout 任务。最终评估开始后，不因结果不理想而解除封存重试。
6. 最终结果、失败状态与错误证据都持久化；需要更改数据、候选或实验配置时创建新协议。

这是应用层的研究纪律。拥有本地数据或代码权限的人仍能绕过应用读取数据，因此这里不声称提供不可绕过的安全封存。

## 经济性失败记忆

失败记忆应包含原指标与上下文，而非只保存“这个因子不好”的自然语言判断：

- 数据指纹及研究验证时间范围。
- 执行配置指纹：费用、冲击、成交量限制、价格和组合参数。
- 候选表达式／假设与本次指标。
- 失败类别、证据以及可能的下一步研究约束。

允许使用真实得到的成本侵蚀、成本后负表现等证据。只有提供了可核查的子期结果时，才讨论跨阶段不稳定；不从整段收益凭空生成 regime 诊断。没有有效研究上下文时停用记忆检索，窗口指向测试集或与 holdout 重叠时拒绝写入研究记忆。

真实上游 LLM 循环可使用以下增量钩子：

```bash
export AQR_RESEARCH_CONTEXT=/absolute/path/to/research_context.json
export QLIB_FACTOR_HYPOTHESIS_GEN=quantaalpha.research.hooks.MemoryAwareHypothesisGen
export QLIB_FACTOR_SUMMARIZER=quantaalpha.research.hooks.MemoryAwareFeedback
```

上下文至少声明 `dataset_fingerprint`、`validation_window`、`execution_fingerprint` 和 `purpose: "validation"`；有 holdout 时同时声明 `holdout_window`。接入后仍使用 QuantaAlpha 原研究循环，而不是替换其因子生成与回测基础。

## 成本与可成交性

沿用 QuantaAlpha `BacktestRunner` 和 Qlib exchange 配置，显式保存 `deal_price`、开／平仓费用、最低费用、市场冲击、交易单位与成交量限制。比较策略时保持这些参数一致，并保留成本前后结果。

日频成交量限制和冲击近似不等于真实订单簿重建。v1 未验证排队位置、撮合延迟、盘口撤单或完整市场冲击；真实研究应进一步做费率、流动性和冲击敏感性分析。

## 等预算消融

至少比较 `memory_on` 与 `memory_off`：

1. 使用相同的数据指纹、时间窗口、模型和成本配置。
2. 使用相同的初始条件、随机种子和候选评估次数上限。
3. 分别记录代码／表达式失败、训练失败和有效回测，避免只统计幸存者。
4. 在研究验证窗口比较结果；不能让一组先看 holdout，再帮助另一组改进。
5. 同时报告最优验证表现、有效尝试比例、重复失败、耗时和实际预算消耗。

确定性提案演示中的消融主要验证记忆是否改变提案与记录流程。研究记忆能否改善真实 LLM 的样本外研究效率，需要多随机种子、多个数据阶段和真实模型调用的进一步实验。

## 证据导出与验收

研究 API 的导出应包含协议与状态、数据和执行指纹、四窗口、候选及冻结摘要、验证指标、最终结果（若已完成）、事件轨迹及实验配置，不包含 API Key。对比报告应保留失败实验，不仅展示收益最高的一次。

工程验收至少覆盖：合法窗口可运行、重叠／purge 不足会拒绝、研究期间不评估 holdout、候选冻结摘要一致、重复最终评估被拒绝、数据／执行上下文不匹配不复用记忆、上游真实 Qlib 回测能结束、前端构建通过。

合成数据用于工程验证；真实市场结论应来自明确版本的真实数据和上述研究协议。样本外表现、成本后收益和多轮稳健性是必须报告的证据，高回测收益本身不足以证明实盘盈利。
