## 哪些能力来自上游

QuantaAlpha 已经提供 LLM 驱动因子挖掘、假设与代码实现、轨迹进化、因子库、独立回测与网页工作台。其回测模块复用 [Qlib](https://github.com/microsoft/qlib) 的数据、模型与组合评估能力。这些能力是本工程的基础，不应列成本项目从零实现的成果。

上游还引用了 [RD-Agent](https://github.com/microsoft/RD-Agent)、[AlphaAgent](https://github.com/RndmVariableQ/AlphaAgent) 等工作。引用某论文与当前同名仓库主分支严格对应，是不同的事实；需要论文复现时应核对具体提交与实验设置。

## 本项目新增的工程增量

| 增量 | 解决的问题 | 验证方式 |
| --- | --- | --- |
| 经济性失败记忆 | 代码能运行但成本后表现差，或已有验证证据显示策略失效，下一轮容易重复同类尝试 | 保存失败标签、原指标和数据／执行上下文；比较有无记忆的候选与结果 |
| 四窗口研究协议 | 模型调参、Agent 候选选择和最终测试反复共用同一段数据 | 独立 `train / tune / research_validation / sealed_holdout` 与 purge 检查 |
| 冻结与一次性 holdout | 最终测试后仍修改候选，会把测试集逐渐变成调参集 | 冻结候选摘要、原子状态转换、拒绝二次最终测试 |
| 等预算消融 | 多做实验可能被误认为记忆机制更好 | 使用相同数据、初始条件与候选评估预算；分别记录成功和失败评估 |
| 可审计实验工作台 | 无法解释某个策略为何被选择，也难以复算 | 保存协议、候选、事件、配置、结果和导出证据 |

这些是本工程的增量设计和实现目标。是否构成论文层面的新方法，需要进一步文献比较与实验支持。尤其 RD-Agent 已有失败经验管理，因此“加入记忆”本身不足以作为新颖性结论。

## 演示与真实研究的区别

无密钥演示使用合成日频行情与确定性候选提案，验证数据准备、Qlib 模型训练、回测、状态管理和证据导出的工程链路。它不验证真实 LLM 的研究能力，也不提供市场盈利证据。

真实 LLM 挖掘继续使用上游的模型配置和研究循环。新增记忆钩子通过 `AQR_RESEARCH_CONTEXT` 读取显式验证上下文；缺少上下文时不应猜测样本范围。只有来自研究验证窗口的结果可以进入研究记忆，holdout 结果用于最终报告。

## 贡献约定

1. 保留原有模块和归属，优先在 `quantaalpha/research` 中增加研究协议能力；必要的 API／前端改动保持可审阅。
2. 每个实验改动注明所用数据版本、标签跨度、时间窗口、成本配置和随机种子。
3. 报告实际执行的模型与数据来源，分别列出通过、失败、跳过和未运行的检查。
4. 不将曲线展示、合成数据实验或一次高收益回测描述为可实盘盈利的证明。
5. 更改研究协议或候选后建立新协议，保留旧冻结记录及其最终结果。
